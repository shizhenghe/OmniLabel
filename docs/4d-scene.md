# 4D 整场景标注与地图重建

4D 工作区使用 **clip 级别的世界坐标场景**。整个 clip 的扫描重建为同一张地图，
切换时间轴只更新活动相机、当前位置和目标轨迹，不把地图切回一张孤立的单帧点云。
原始点云、标定以及每帧车辆位姿不会被重建过程覆盖。

## 数据与坐标

每帧仍使用 [数据格式](data-format.md) 中的 `ego_to_world` 和 `lidar_to_ego`。
原始的 LiDAR→世界变换为：

```text
world_from_lidar = ego_to_world @ lidar_to_ego
```

重建输出 `SceneMap.world_from_lidar[frame_id]`，它是当前场景中**实际使用的变换**。
相机投影时先将世界坐标标注乘以它的逆变换，再走该帧的 LiDAR→ego→camera 标定链。
因此使用 ICP 校准后的轨迹也可以一致地投影到相机图像。

## 重建、完整点数与质量

原始扫描、4D 融合和地图导出不设置固定点数上限，也不再把地图静默截取为 50 万点。
外部 NPY 文件以内存映射读取，融合按 10 万点的工作块处理；这是临时工作内存大小，
不是输入上限。地图缓存使用完整 NPY，GET 地图默认返回全部点。
大型地图可使用连续分页 `scene/map/points?offset=0&limit=100000` 或下载 `scene/map.npy`；
分页返回原始地图索引、总数和 next_offset，不做随机抽样。有限的机器内存、磁盘和浏览器显存
仍会限制实际可处理的数据规模，完整 JSON 响应也需要相应内存；不要把无限点数理解成无限资源。

可选择四种融合方式：

浏览器在写入 GPU Float32 顶点前先减去局部渲染原点，避免 UTM 等大坐标丢失厘米级细节；
标注、导出与鼠标拾取仍使用真实世界坐标。这个渲染平移不会修改源扫描或注册位姿。

- **full / 全分辨率**：保留所有静态实测点，包括重复观测；不做体素降采样。
- **detail / 强度细节**：使用主地图与细节体素中较小的分辨率，保留每格实际测得的最强反射点及其原始强度、标签。
- **surface / 实测表面**：两次流式遍历，保留最靠近最终体素质心的实测点及其配对强度、标签，避免仅按最高强度偏向离群点。
- **centroid / 均值降噪**：对体素内位置、强度求均值，并合并语义投票。它可减少噪声和点数，但会弱化窄标线的强度差异。

可显式开启统计离群点过滤；默认关闭，避免把合法的稀疏远处点自动删除。
开启后按每帧近邻平均距离与标准差识别孤立点，结果记录 `excluded_outlier_points`。
动态框/语义过滤单独记录 `excluded_dynamic_points`；原始扫描始终保留。
`input_point_count`、`point_count`、`fusion_mode` 和各删除计数可用于核对完整性。

**使用位姿**：对全 clip 应用输入车辆位姿和外参，适合已有高质量定位或 SLAM 的数据。
如果已做过 ICP，重建保留注册坐标，不会因标注修改悄悄退回原位姿。

**多尺度 ICP**：以输入位姿初始化，采用三阶段体素及逐渐缩小的对应距离，
使用截尾对应与 Huber 加权刚体拟合，将当前扫描对齐到最近若干帧组成的局部子地图。
默认子地图为 5 帧，基准配准体素 0.1 m；配准采用空间均衡的确定性样本，
减少点云按激光线束/数据包排序时线性抽样造成的偏差。
默认每阶段最多 15000 个优化样本，可把 `registration_sample_size` 设为 0 使用全部配准体素；
这些仅是求解器的样本，最终地图仍重新读取所有原始点，与优化样本预算无关。

每帧至少需要 30 个非共线的静态点及足够重叠。
默认粗阶段对应范围 3 m，最终阶段为 0.2 m；最终重叠率需至少 25%，
inlier RMSE 不超过最终对应距离的 60%。每阶段报告体素、重叠率、RMSE、迭代数和收敛状态，
同时报告位姿修正量。无重叠、退化几何或低质量结果会明确失败。

ICP 仍是局部配准，没有回环检测或全局位姿图优化；目前输入也未提供逐点时间戳，
不能执行真实扫描去畸变或运动补偿。对于长距离采集，应优先导入经过外部定位/SLAM、
时间同步和运动补偿的高质量位姿，再以固定路面、墙体、路牌等实测目标检查重影与漂移。
调小体素或增加点数无法修正错误的外参、时间戳和缺失观测，也不生成未测到的路面纹理。

## 地面标线与反射强度

车道线和箭头通常与路面高度接近，单靠高度着色或统一的 road 语义颜色看不到漆面差异。
需要输入实际采集的 **XYZI 反射强度**，并使用强度显示。只有 XYZ、强度恒定、扫描本身没
采到标线，或配准偏差使线条重影时，平台不能凭空恢复真实漆面；可结合相机图像人工标注。

细节保留模式使用主地图体素与 `detail_voxel_size` 中较小的分辨率，默认细节体素为 **0.05 米**。
每个体素保留最高反射强度对应的 **原始实测 XYZ 与强度、标签**，避免把窄标线和暗路面平均成灰色。
它不会自动猜测地面或生成未测到的道路纹理；全分辨率模式则保留每个已采集的点。

地图记录 `effective_voxel_size`、`point_reduction`、`intensity_available`、
`intensity_has_contrast`、`intensity_range` 和 `fusion_version`。旧版缓存会要求重新重建，
已有标注和注册位姿继续保留。XYZ-only 输入补零是计算兼容行为，不会生成反射强度。

新增的 **道路标线 · 强度演示** (`demo-ground-detail`) 是明确标注为合成的演示 clip：
白色虚线、黄色边线、方向箭头在相机渲染与点云中使用同一几何，漆面点有较高的合成强度。
启动时仅在该 clip 不存在时添加，已有 `demo` 点云、图像、标注均不会被替换。
新安装生成的默认 demo 也含这些点，历史 demo 本来缺失的反射点不会被悄悄补写。

## 车道线绘制

1. 进入「车道线标注」，保留「整场景 4D」可跨帧共享道路矢量。
2. 选择车道线、实线、虚线、停止线等类别，点击「开始绘制车道线」。
3. 在俯视图沿道路逐点点击，至少两点后按 Enter 或「完成绘制」。
   Backspace 撤回一点，Esc 取消草稿。人行横道和导向箭头轮廓至少三点，保存为闭合面。
4. 选中矢量后在右侧修改每个顶点的 XYZ，点击「保存标注」。
   世界坐标矢量在切帧时保持，左侧图像显示当前时刻的标注投影。

「点云着色 → 反射强度」按当前可见点的强度范围显示灰度。
「仅看地面」可隐藏树冠、建筑等遮挡，使用右侧地面参考高度 ± 高度半带宽；
世界坐标高度并不总是 0，坡道或起伏路面需调整范围或关闭高度筛选。
绘制时 XY 取鼠标地面平面交点，附近实测地面点提供 Z；无邻近点时使用参考高度，
需要逐顶点核验高程，平台不会自动估计未测得的坡度。
细节保留也可能保留高反射离群点，不能替代传感器强度标定、去噪和精确位姿。

## 场景标注与时间轨迹

场景标注保存在 `scenes/{clip_id}.json`，包含一层持久世界坐标矢量，以及跨帧的目标轨迹：

```json
{
  "revision": 2,
  "coordinate_frame": "world",
  "vectors": [],
  "tracks": [{
    "id": "vehicle-001",
    "label": "vehicle",
    "mode": "dynamic",
    "keyframes": [
      {"frame_id":"frame-000", "center":[10,0,0], "size":[4,2,1.6], "yaw":0},
      {"frame_id":"frame-010", "center":[15,0,0], "size":[4,2,1.6], "yaw":0.2}
    ]
  }]
}
```

动态目标在关键帧之间按**实际时间戳**插值中心和尺寸，朝向沿最短角距离插值。
关键帧区间之外保持最近端点；没有声称自动估计真实运动。静态目标始终使用第一关键帧。
初次打开旧版 clip 时，系统把旧的单帧框转换为世界坐标轨迹，并合并相同的世界矢量，
原来的单帧标注仍保留。对于多帧世界位置、朝向基本不变的目标会初始化为静态目标，
用户仍应核验它的静态/动态属性。

重建可选择排除动态目标。静态车辆不会仅因为语义类别为 vehicle/car 就被删除；
场景中的静态/动态轨迹属性优先于这种类别假设。未知运动且只有一帧观测的车辆默认动态。
3D 框采用 yaw-only 长方体，不能完整表达翻滚、俯仰；高度倾斜的传感器/物体需要额外适配。

## 鼠标直接调整 3D 框

在「3D 目标检测」点击框或右侧目标列表，立即出现尺寸控制柄。
拖动红色「长±」、绿色「宽±」、蓝色「高±」分别调整尺寸，拖动中心「↔」移动位置；
无需手动输入数值。尺寸调整时对侧框面固定，中心位置随被拖动的框面一起变化。
右侧坐标、尺寸和七路图像投影实时更新，完成后点击「保存标注」。
全场景中目标较小时，点击「聚焦目标」放大到所选框附近，再拖动可进行更精细的调整。
「旋转」模式可拖动控制柄调整航向，「平移」模式提供单轴移动。
俯视图中高度方向沿视线，修改高度需切回「透视 3D」；控制柄重叠时旋转观察角度。
世界坐标轨迹在当前时刻拖动时自动创建或更新关键帧。

## 保存、缓存与交换

- 场景保存有独立的 revision。并发或过期保存返回 409，避免覆盖其他修改。
- 地图缓存和原始数据分开保存。修改场景/逐点标签后，缓存会被标记过期，重建以刷新动态过滤。
- 已注册轨迹独立保留；缓存过期不会使相机逆变换退回旧坐标。
- `export` JSON 和 `export.zip` 包含 `scene_annotations` 与 `scene_registration`。
  注册变换在跨实例导入时校验并恢复，因此世界坐标标注保持一致。
- 导出中的 `scene_map` 仅包含轻量诊断元数据；点云地图可重建，不把未校验的缓存作为真值导入。
- 原始逐帧图像多边形和逐点语义仍随帧保存；模型预标注可读取场景投影到当前帧的框和矢量，
  但模型结果必须人工审核。

完整接口见 [scene-contract.md](scene-contract.md)。
